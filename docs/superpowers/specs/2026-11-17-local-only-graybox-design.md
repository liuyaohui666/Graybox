# Graybox 本地个人版设计

## 目标

将 Graybox 从当前依赖云端账号、服务器和多人协作的版本，重构为只供本人使用的 Windows 桌面软件。所有项目、想法、实验、标签、历史记录、头像和附件保存在本机，并可通过一个自包含迁移包迁移到另一台设备。

## 范围

保留：

- 项目、想法、实验、优先级、进度和原生标签。
- 项目内想法、独立想法、实验分支和来源关系。
- 五类实验报告：做了什么、什么行不通、可复用经验、待定事项、其他。
- 评论、修改历史、头像、截图、短视频、静态网页和 GitHub 地址。
- 附件在详情页的预览和末尾管理。
- Codex 通过本机 Skill/CLI 读取和写入 Graybox。

移除：

- 登录、邀请码、初始化码、团队成员和团队管理。
- 云端地址、云端数据库、Agent 配对、远程同步和联网协作。
- 赞同、消息通知和多人权限判断；历史记录中的作者信息作为普通署名保留。

## 推荐架构

桌面端使用 Tauri。应用启动一个仅绑定 `127.0.0.1` 的本地 API，桌面前端和 Codex CLI 共用同一套业务接口。

- 数据库：SQLite 单文件，启用外键和事务。
- 附件：应用数据目录下的 `attachments/`，文件名使用内容哈希或不可猜测 ID。
- 头像：应用数据目录下的 `avatars/`。
- 本地配置：只保存数据目录、数据库版本和迁移包版本，不保存云端凭据。
- 服务器：不再启动 PostgreSQL，不读取 `GRAYBOX_SERVER_URL`，不需要网络。

推荐的数据目录：

```text
D:\\Graybox/
├─ graybox.sqlite
├─ attachments/
├─ avatars/
└─ backups/
```

## 数据迁移

### 云端到本地

提供一次性导入工具，从现有云端导出的 JSON、附件和头像生成 SQLite 数据库。导入过程保留原 UUID、时间、来源、版本、报告、标签和附件关联；云端作者 ID 转换为本地署名，不再作为登录权限使用。

导入前建立本地备份。遇到 UUID 冲突时停止导入并报告，不覆盖已有记录。

### 设备到设备

导出生成一个 `.graybox` 文件，本质是带清单的 ZIP：

```text
graybox-YYYYMMDD-HHmmss.graybox
├─ manifest.json
├─ graybox.sqlite
├─ attachments/
├─ avatars/
└─ README.txt
```

`manifest.json` 包含格式版本、导出时间、数据库 SHA-256、附件清单和记录统计，不包含密码或云端令牌。导入时先校验清单和哈希，再在临时目录恢复，最后以事务方式替换或合并。

默认导入策略为“完整替换当前本地库前先自动备份”；另提供“合并到当前库”，按 UUID 去重，冲突记录停下并显示差异，不静默覆盖。

## UI 调整

- 首页改为“我的工作台”，不再显示云端状态、成员区和团队入口。
- 左侧保留项目、想法、实验、标签和设置。
- 设置中提供“数据目录、导出数据、导入数据、打开数据目录、检查数据库”。
- 头像菜单改为个人头像、昵称、数据管理和退出程序。
- 所有“团队可见”“消息”“配对”等文案移除或改为本地历史说明。
- 保留深色工作台配色和当前五分类实验卡片布局。

### 学习模块

左侧新增独立的“学习”模块。结构为“学习方向 → 分支 → 知识点”。知识点包含未开始、学习中、已掌握、待复习四种状态，并支持笔记、标签和下次复习日期。学习数据与其他本地数据一起进入 SQLite 和 `.graybox` 迁移包。

## Codex 接入

Skill 改为本地模式：

- 自动发现本机 Graybox 数据目录。
- CLI 直接连接本地 API，不需要 `GRAYBOX_CLIENT_CONFIG`、配对码或远端 endpoint。
- 每次写入仍保留稳定请求键、同步日志和读回核对。
- Skill 明确说明数据只保存在本机，并支持“导出迁移包”与“导入迁移包”。

## 验收标准

1. 断开网络后，桌面程序仍可创建、编辑、搜索和查看全部本地记录。
2. 首次运行不出现登录、邀请码、配对或云端地址输入框。
3. 旧云端项目、想法、实验、标签、历史和附件能导入并通过数量与 UUID 核对。
4. 导出的 `.graybox` 在另一台 Windows 设备导入后，记录、附件、头像和关系一致。
5. 导入损坏包或冲突数据时不破坏当前库，并给出明确错误。
6. Codex 在本地 Skill 下能读取已有记录、写入新记录并完成读回核对。
7. 数据库、附件和导出包不包含密码、令牌或云端登录会话。

## 明确不做

本阶段不删除云服务器上的数据，不修改公开仓库的团队版发布说明，不实现多人同步，也不承诺未来本地库与旧云端自动双向同步。云端数据先作为导入来源和只读备份保留。
