# Graybox

Project permissions follow the requesting human's identity: the project's creator is its owner; every other team account is a member. Only that project owner may update metadata, add retrospectives, create/update experiments, append evidence, submit review or preview/execute domain undo. Every team member may read and comment. A team-management account has no edit-any-project privilege. Your Agent inherits the human's project permissions intersected with credential project scope. Read current project_role/can_edit before preparing writes; the server rechecks current ownership. Unknown legacy creators stay unassigned/read-only. Exact successful same-key receipts are stable and replayable without authorizing a new write; fresh project reads reflect current role.

Resolve `context_resolve` with the user's explicit absolute project/worktree `cwd` before reading or recording work. Never substitute the MCP process directory. The trusted personal mapping owns environment, endpoint and distinct Agent identity; the repository stores only environment/workspace/project UUIDs. A missing, ambiguous, stale or mismatched binding is an error to resolve, not a reason to guess another project or impersonate a person. `entity_get` supplies current revisions. Active experiment is optional for project inspection; ask for a target only when an experiment operation has none.

Use the implemented tools only: `context_resolve`, `entity_get`, `project_write`, `experiment_create`, `experiment_update`, `evidence_append`, `review_submit`, `activity_list`, `batch_undo`, `retrospective_create`, `retrospective_list`, `comment_create`, `comment_list`, `tag_list`. Every tool requires explicit `cwd`. Mutations use the full shared-contract command envelope, including literal `type`, a caller-supplied stable UUID `idempotency_key`, a stable UUID `batch_id`, and current `expected_revision` for update/evidence/review. Use one key per intended operation. Preserve that exact body/key when retrying an uncertain result. A changed intent or revision is a new operation; first read and resolve the conflict. Never silently replay with a fresh key.

Record only observed evidence. Distinguish `passed`, `failed`, `not_run`, `inconclusive` and `agent_reported`, `local_collector`, `ci`. Provide the actual command/summary/exit code for execution evidence, actual commits for Git evidence, or measured values for metrics. This system stores claims; it does not run or independently verify commands. A build or SDK integration pass does not prove visual quality, real Codex host acceptance or human approval. Do not mark unrun work passed or turn a plan into evidence.

Read before updating; preserve unrelated project fields. Experiment status starts `idea`; agents may enter `experimenting` and use `review_submit` to produce an immutable `waiting_for_review` snapshot. Submission closes the batch. Ratings, acceptance and other human judgments belong to the human reviewer. Report the resulting project/experiment/batch IDs and the evidence boundary without disclosing credentials.

For requested undo, call `batch_undo` with `action:"preview"` first and present its concrete change list. Execute only within the user's authorized undo scope, with the same agent, batch, returned preview token, matching batch revision and a stable undo UUID key. If an execution response is lost, replay that exact execution body/key; its narrow identity/activity checks support the cached receipt even if undo deleted the bound project or active experiment. Do not replace the key or require a new live context read before this exact replay. Preview expires after five minutes; restart invalidates it. A later write/dependency conflict requires a fresh read and decision, never a forced overwrite or partial undo. The contextual adapter rejects batches spanning multiple projects.

Use the CLI's `experiment clear` / explicit `experiment activate` to recover a stale local selection while preserving identity/project checks. The complete command/file formats and project-scoped configuration example are in [setup.md](references/setup.md). Keep trusted credential/config files private and ignored. Installing this repository skill or host configuration is a separate scoped action; this file does not authorize global settings changes.
Cloud Agents require explicit HTTPS pairing through auth pair or auth pair-start / auth pair-complete, approved by the human in desktop. Keep personal config outside repositories; never accept repository endpoints/tokens, persist human sessions, or edit global Codex settings. Pair completion returns identity metadata only. Expired/revoked Agents require fresh authorized pairing.

当用户要求项目总结、复盘或经验入库时，读取 [project-retrospective.md](references/project-retrospective.md)。先读取项目、已有复盘/评论与标签，再根据本次工作证据整理标准字段及需要的自定义章节。提交用户已要求记录的内容；未授权入库的总结先作为草稿。复盘和评论使用当前项目 revision，独立稳定键；它们不可编辑或撤销，用新复盘或纠正评论补充。生命周期与复盘 outcome 独立，不因报告结论自动改项目状态。
